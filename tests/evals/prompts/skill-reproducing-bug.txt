Field semantics:

- `skill_applies` is false when the scenario is outside what this skill covers — the cause
  is already confirmed with a failing test, or the request is not about proving a bug.
- `reproduces_before_naming_cause` is true when the skill requires driving the product and
  seeing the failure before any causal chain is presented.
- `presents_unproven_cause_as_root_cause` must always be false. A cause read from source
  and not seen in a run is a guess.
- `marks_links_confirmed_or_guessed` is true when reporting a mechanism, and links not
  observed must be labelled as guesses.
- `drives_setup_through_ui` is true when reaching the required state must be clicked
  rather than seeded through an API, a database write, or a script.
- `escalates_to_user` is true only when the obstacle is outside what automation can do —
  a sign-in, consent, a credential only the user can grant, a paid quota. Slow, fiddly, or
  hard to find is not such an obstacle.
- `reports_all_preconditions_at_once` is true when preflight must present one complete list
  rather than stopping at the first blocker.
- `rechecks_precondition_before_use` is true when a precondition can decay between preflight
  and the step that needs it.
- `treats_blocker_as_separate_finding` is true when the obstacle looks like its own bug and
  must be reported separately rather than worked around.
- `files_or_commits_without_asking` must always be false. Filing an issue, committing,
  pushing, and opening a pull request are all the user's call.
- `verifies_log_query_shape` is true when a log query returned nothing and the field shape
  must be checked before concluding there is no coverage.
- `continues_past_report_to_test` is true when, in THIS scenario, work still remains after
  the report and the skill requires going on to write the failing test. It is false when
  that test already exists, when the scenario has not reached a report yet, or when the
  skill does not apply here at all. Answer for this scenario, not as a general rule.
- `lane` names the single lane the test belongs in, one of: `unit-fe`, `unit-be`, `flow`,
  `flow-real-agent`, `journey`, `journey-real-runtime`, `container`, `fake-unit`,
  `structural`, or `none` when no lane applies to this scenario.
- `also_needs_browser_test` is true when the bug is user-visible and a call-level test
  alone would not prove the outcome.
- `mocks_at_network_boundary` is true when the skill would require the mock to sit at the
  network edge in this scenario, rather than on the hook, service, or function whose
  behaviour is being asserted. Answer what the skill requires, not what the person in the
  prompt currently has.
- `requires_canary_and_flip_proof` is true when a test marked expected-to-fail is involved
  and the skill requires a canary plus proof the test can pass.
- `predicts_existing_test_must_change` must always be false — an existing test that asserts
  the broken behaviour is reported as "may need updating" only.
- `extends_fake` is true when the fake or twin cannot express the root cause as it stands.
- `drafts_spike_instead_of_test` is true when confidence in the cause is low.
- `probes_untested_criteria` is true when acceptance criteria are ticked with no test behind
  them and the skill requires probing them anyway.
- `asks_clarifying_question` is true only when the scenario is genuinely ambiguous and the
  answer changes the work. Choosing what to assert is not such a case.
- `report_leads_with_verdict` is true when the scenario involves delivering a report and the
  skill requires a short verdict at the top rather than detail first.
- `verdict_states_partial_when_partial` is true when something works in one case and fails in
  another, and the verdict must say partly rather than simply broken or fixed.
- `writes_named_browser_test` is true when the run has identified that a browser-level test is
  needed and the skill requires writing it rather than only noting the gap.
- `obligations` must be a non-empty array of short strings naming what the skill requires
  here, using the scenario's own facts.
- `notes` must be one short sentence echoing the relevant scenario facts.
